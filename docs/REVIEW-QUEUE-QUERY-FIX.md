# 项目待审核数量查询修复

日期：2026-10-23

## 原因

原 warehouse_query 只授权读取报告节点绑定的冻结数仓快照。普通项目对话和定时任务对话没有这类快照，因此无法查询实时审核队列；这不表示文章没有入库。

## 修复

新增 project_review_queue 工具，由服务端根据对话拥有者、项目归属、团队成员权限定位项目，模型不能指定任意用户或项目。工具同时要求 chat 和 articles.read 权限，审核员不会因此获得对话能力。定时对话使用持久化的任务来源和项目团队，不依赖用户当前浏览的团队。

统计项目下未删除画布的 live 文章，排除模拟记录和已删除记录。待审核按 review_status=pending；预警按 decision=report/review，与文章列表一致。查询返回全部文章、全部待审核、预警文章、预警待审核四个数量以及时间和审计 ID。查询异常不返回零。原报告快照权限保持不变。

## 画布运行的独立问题

历史存在 17 节点 succeeded 运行。最近两个 sgm_warehouse_report 节点运行失败原因为“指定时间范围没有入库文章，请修改报告时间范围”。报告时间窗为空与项目库中有存量文章可以同时成立；本次未调整报告时间范围或重跑画布。

## 明细查询补齐

数量工具原先没有文章投影，导致后续“给我明细”只能请求用户提供文件。现在同一 project_review_queue 工具支持 include_details=true，返回标题、原文链接、来源、发布时间、入库时间、风险、审核状态和摘要。review_status 默认 pending，可选 all 或其他审核状态；alerts_only 可限定预警文章。每页默认 30、最多 50 条，通过 next_offset 继续，响应包含 total 和 has_more，不把部分页冒充全部。

明细与计数共用完整权限校验和 live/未删除过滤，不接收模型传入的项目或用户，不暴露原始采集载荷。分页按入库时间和 ID 倒序；并发入库或审核可能改变后续页，响应明确说明实时分页语义。新增回归覆盖分页、字段、状态改变、预警筛选及越权拒绝，本轮相关测试合计 10 passed。真实数据验证脚本逐页核对数量与 ID 唯一性，证据输出到 output/verification/review-queue-details-live.json。

## 宿主适配参数修复

后续真实对话暴露出验证缺口：DeerFlow 的工具封装将参数转换为 MappingProxyType，QueueOptions 的 strict 校验拒绝这种只读映射，连空参数统计也失败。直接传 dict 的旧测试没有覆盖这一边界。现于插件入口转成普通字典后保留严格字段校验；不放宽未知参数、用户归属和权限约束。

验证脚本改为通过宿主 _build_tool 的 coroutine 调用，覆盖真实的参数包装、JSON Schema 校验、身份解析和 64 KiB 返回限制。明细增加字节预算，每页可少于请求条数，next_offset 按实际返回条数递增。新增宿主封装与长字段回归，相关测试合计 11 passed；普通/定时对话真实库逐页验证成功。本验证没有重新运行 LLM 或发送通知。
