# 页面卡顿排查与修复（2026-10-23）

## 原因与处理

前端原启动命令是`next dev --webpack`。日志显示访问项目/团队页面首次编译耗时10至28秒，随后持续发生`ERR_MEMORY_ALLOCATION_FAILED`，最终`JavaScript heap out of memory`并退出3000端口。Gateway日志同样出现过`MemoryError`。这些是当前机器上的实际记录，不只是浏览器动画问题。

日常启动已改为`next start`，先执行`build-local.ps1`预构建全部页面。源码调试仍可明确加`-Development`；不能把开发服务器作为长期日常服务。正式构建经过Webpack、TypeScript和页面生成，日志保留于`output/verification/performance/production-build.log`。构建本身的峰值RSS约3.6GB，发生在启动前。

运行历史每3秒获取完整图定义：8条记录约296KB；现在查询仅投影运行摘要，完整冻结图仍由详情接口保留，列表变为4088字节。轮询改为请求结束后调度下一次，隐藏标签页暂停，运行历史15秒/文章列表10秒更新。正在执行节点的详情仍每2秒观察。

运行快照界面拆分为稳定组件，记录按50条逐步展示，完整JSON仅在展开时序列化，避免每次轮询重复构造大型隐藏文本。

## 实测范围

同机生产版本单次浏览器观察：项目页面文档load约696ms；点击项目至画布可见2959ms；运行页签72ms、文章页签44ms、节点配置78ms。页签数值是面板出现时间，不代表全部数据请求完成。后端单次请求仍约0.7至1.4秒，机器负载与数据量会影响结果；不能将本次小样本视作生产SLA。

服务启动后前端进程工作集约127MB，Gateway约358MB；本轮未改操作系统内存设置，也未结束其它工程进程。原开发日志已脱敏摘录保存。

证据目录：`output/verification/performance/`，包括前后API体积/耗时、浏览器交互时延、构建日志及原内存错误。浏览器画布/调度面板快照位于`output/playwright/perf-*.yml`。

回归：7项UI测试通过（包含慢请求不叠加、隐藏页暂停/恢复、卸载停止）；13项真实MySQL针对性测试通过（任务、API权限、轻量列表和独立调度）；扩展TypeScript/Vite及原生生产构建通过。

浏览器复查报告HTML仍可预览，关闭的完整快照详情不挂载大型JSON文本。节点触发设置拆出独立组件，源码规模基线通过；旧ACE status/diff/HEAD不变，未提交或推送。

## 项目、对话、团队切换专项复测

用户明确卡顿发生在跨页面切换后，在上述生产构建上继续复现。进入已有上汽通用报告对话，点击至历史接口返回耗时7422ms；多个并发请求耗时3至7秒。根因是Gateway每次HTTP请求都校验13项路由权限，ACE提供者每项分别读取团队和当前团队，单请求26条SQL，冷连接测量637ms。对话页面同时请求历史、技能、模型等接口，重复查询进一步排队。

增加可选`aauthorize_many(requests)`通用钩子；旧提供者保持原逐项行为。ACE在一批校验内每用户只读取一次成员关系，13项权限合计2条SQL（同样包含新连接初始化的测量143ms）。下一请求重新查库，撤权和团队切换不依赖缓存过期。工具/技能候选列表复用同批规则。HTTP资源归属、原生owner过滤、PAT与CSRF检查均继续执行。

首次进入指浏览器刷新后的首次客户端导航，静态资源仍可能命中浏览器缓存；返回页使用正常应用缓存。团队页等待本次成员请求成功，对话页等待历史响应；另加回答文本渲染检查。项目列表使用当前团队上下文。小样本不等同于生产SLA。专项两轮切换没有观察到超过50ms的浏览器主线程长任务。

新增及既有原生权限回归40项通过，扩展真实MySQL权限回归6项通过；包含批处理失败策略、取消、撤权、用户隔离。原生测试使用独立不存在的`DEER_FLOW_CONFIG_PATH`，避免测试桩用户读取本机真实团队策略；生产配置未修改。真实登录复核审核员只能访问文章、编排师不能管理成员，跨团队角色变化与文章隔离正确。SGM画布revision仍为8，未执行模型任务或推送。
